types of faults:
transient - sporadic behaviour
intermittent - appears several times, but not periodic
permanent - exists permanently until failty component is removed or repaired
failure models:
	crash failure - system works -> system failure (system does not work anymore (at all))
			remains stopped
			failure - >stop (can be detected by other processes; it does not produce output
			failure detector: detects failures (or presumes something failed)
	omission failure - where server does not respond to request
			system works, but does not receive a request
			system works, but does not respond
	timing failure - system works, but response is not received when expected; does not meet deadline
			ethernet: two parites, it waits random hits the same, it waits again
			heavily loaded, no guarantee for, no guarantee with timing failures.
			server responds too late: performance failure
			aavailability related: perceived respons time for user
	response failure
			incorrect response - precision problem in search engine or wrong loT sensor
			artificial intelligencesystems and response (compliancy)
			how to know when system says yes (explainability of AI)
			state transition failure: wrong actions triggered (server deviates from the correct flow of control)
	byzantine - arbitrary failure
			system appears to work correctly, but response is not correct
			hard problem; how to detect this behavior -> collaboration 
			(malfunctioning loT sensor, algorithm with wrong arithmetic operation, artificial intelligence and trust, adversary)
